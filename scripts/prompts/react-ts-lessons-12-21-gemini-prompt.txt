## LESSON SPEC - Generate lessons 12 to 21

### L12: Props Drilling
Concept: passing props through intermediate components that don't use them.
Build: A theme color set in a grandparent App, passed through a middle Panel component, consumed by a leaf Text component.
Key teaching: props flow one way - down. Intermediate components must explicitly pass props they don't use themselves. This creates repetition - that's the pain that motivates Context later.
New concepts: multi-level prop passing, reading props at leaf level, recognising the drilling pattern.

### L13: Default Props
Concept: optional props with default values using destructuring defaults.
Build: A Badge component with required label and optional variant ('primary' | 'secondary') that defaults to 'primary'.
Key teaching: ? makes a prop optional in the interface. Default values go in the destructuring parameter, not separately. TypeScript knows the prop might be undefined without a default.
New concepts: optional props with ?, union type for variants, default parameter values in destructuring.

### L14: Children Prop
Concept: the children prop - passing JSX content between component tags.
Build: A Card wrapper component that renders any content passed between its tags.
Key teaching: children is a special React prop. Type it as React.ReactNode. The component renders {children} in its JSX - it doesn't know or care what's inside.
New concepts: import { ReactNode } from 'react', children: ReactNode in interface, {children} in JSX.

### L15: TypeScript Interface for Props
Concept: interface vs type for props - when to use each, and why interface is preferred for component props.
Build: A UserProfile component with a User interface defining name (string), age (number), isActive (boolean).
Key teaching: interface is extensible and shows better error messages for object shapes. type is for unions, primitives, computed types. For component props, interface is the standard.
New concepts: interface vs type distinction, boolean prop, multiple prop types in one interface.

### L16: Component Composition
Concept: assembling complex UIs from smaller focused components.
Build: A ProfileCard assembled from Avatar, UserName, and Bio sub-components - each receiving only the props it needs.
Key teaching: each component does one thing. Composition means passing the right data to the right component. The parent orchestrates, children display.
New concepts: multiple components in one file, parent passing different props to different children.

### L17: Event Handling
Concept: typed event handlers beyond onClick - onFocus, onBlur, onKeyDown.
Build: A SearchInput component that tracks focus state, clears on Escape key, and shows a hint when focused.
Key teaching: different events have different TypeScript types. KeyboardEvent<HTMLInputElement> gives access to event.key. FocusEvent<HTMLInputElement> for focus/blur.
New concepts: import { FocusEvent, KeyboardEvent } from 'react', event.key, onFocus, onBlur, onKeyDown.

### L18: Conditional Classes
Concept: dynamically applying CSS class names based on state or props.
Build: A Button component that applies an 'active' class when clicked, a 'disabled' class when a prop is set.
Key teaching: className is a string - you build it with template literals or ternary. No special library needed. The class string changes on re-render.
New concepts: className with template literal, ternary inside className, disabled prop pattern.

### L19: Inline Styles
Concept: the style prop in JSX - JavaScript object, camelCase properties, dynamic values from state.
Build: A ColorSwatch component where the user picks a color and the swatch background updates live.
Key teaching: style takes a CSSProperties object. CSS property names are camelCase (backgroundColor not background-color). Values are strings or numbers. Dynamic styles read from state.
New concepts: style={{ }}, CSSProperties type, camelCase CSS properties, dynamic style from state.

### L20: CSS Modules
Concept: scoped CSS using CSS Modules - styles.className pattern.
Build: A Card component styled with a CSS Module file - importing styles and applying styles.card, styles.title.
Key teaching: CSS Modules scope class names to the component. Import the module as an object. Use styles.className in JSX. No global style leaks.
New concepts: import styles from './Card.module.css', styles.className pattern, scoped CSS.

### L21: Styled Component Pattern
Concept: co-locating component logic and styles using a styled-component-like pattern with inline style objects defined at module scope.
Build: A Tag component with predefined style objects for different variants - defined as constants outside the component, applied via style prop.
Key teaching: style objects can be defined as constants at module scope and reused. This is the manual version of what libraries like styled-components automate. Keeps style logic out of JSX.
New concepts: const styles object at module scope, CSSProperties type annotation on style object, selecting style by variant.
