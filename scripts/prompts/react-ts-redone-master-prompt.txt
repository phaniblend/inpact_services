## NEVER INCLUDE THESE - HARD VIOLATIONS

### Imports that do not exist:
- import React from 'react' - not needed since React 17
- import React, { useState } from 'react' - React default not needed
- import { JSX } from 'react' - JSX is a global TypeScript namespace, NOT a React export
- import { type JSX } from 'react' - same error
- import { useState, type JSX } from 'react' - JSX is not exported from react
JSX.Element is available globally in any .tsx file. It does NOT need to be imported.

### React.FC - banned everywhere, zero exceptions:
- Not in mc_options
- Not in example_code
- Not in analog_example
- Not in deepDive fields
- Not in watchOut
- Not in feedback fields
- Not anywhere in the file
If you need to show a wrong pattern, use wrong return type (void), missing return type, or lowercase component name instead.

### Forward references - never reference untaught concepts:
- props of any kind (until props lesson is generated)
- children prop
- ReactNode
- component composition
- prop drilling
- useEffect (until that lesson)
- useRef, useMemo, useCallback, useContext (until those lessons)
- React.FC (never, ever)
- keys in lists (until lists lesson)

### Generic or contextless feedback:
- Never: "Perfect!", "Great!", "Excellent!" as the entire feedback
- Never: "Close, but..." without naming exactly what is close
- Never: "Remember: X" without addressing the specific wrong answer
- Never repeat the correct answer as the feedback for a wrong answer
- Never use the same feedback text across different lessons

### Paal address violations:
- Never: "we", "let's", "the learner"
- Never embed hints or syntax clues in paal
- Never reveal the answer in paal

### Skeletal deepDive:
- Never 1-2 sentence deepDive fields
- Never placeholder text
- Never "..." shortcuts

### Step ordering - locked, never deviate:
1. Imports - one step, named exports only, no React default
2. Module-scope types - interface or type alias, OUTSIDE the component
3. Component shell - explicit `: JSX.Element` return type, empty fragment placeholder
4. State + local variables - useState calls INSIDE the component
5. JSX structure - UI skeleton, no handlers wired yet
6. Handlers - named functions for user interactions
7. Wire handlers to JSX - onClick, onChange, value, conditional render

Rules:
- Steps 1 and 3 are ALWAYS present - never skip or combine them
- Never combine imports + component shell into one step
- Never combine handlers + wiring into one step
