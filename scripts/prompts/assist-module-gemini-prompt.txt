## NEVER INCLUDE THESE - HARD VIOLATIONS

### Invalid imports:
- import React from 'react'
- import React, { useState } from 'react'
- import { JSX } from 'react'
- import { type JSX } from 'react'
- import { useState, type JSX } from 'react'
JSX.Element is globally available in .tsx - never import it.

### React.FC - banned everywhere with zero exceptions:
Not in mc_options, example_code, analog_example, deepDive, watchOut, feedback, or anywhere else.
Wrong patterns to show instead: wrong return type (void), missing return type, lowercase component name.

### Product-specific content - banned:
Never name a specific product, business domain, or app (no "restaurant," "inventory," "shopping cart" as the
worked example domain). The worked example and analog_example must both be generic, small, and self-contained
(a Card, a Counter, a Toggle, a Form field — abstractions, not a business feature).

### Bad feedback:
- Never "Perfect!", "Great!" alone
- Never "Close, but..." without naming the specific gap
- Never repeat the correct answer as the wrong feedback
- Never identical feedback across steps

### Bad paal:
- Never "we", "let's", "the learner"
- Never embed syntax hints

### Bad analog_example:
- Never comment-only prose like // Imagine a kitchen...
- Must be real code in a different domain than the worked example

### Bad dryRun:
- Must start with 🔁 **Think:**
- Must trace specific values through 2+ state changes (or equivalent transitions for non-state concepts)
- Must end with (Hint: ...)
- Never copy the build field into dryRun

### Skeletal deepDive:
- Never 1-2 sentence fields
- All 8 fields fully written, meeting word count minimums

## STRING ESCAPING — check every field before output, this breaks the whole app when wrong
Several fields legitimately contain backtick-quoted technical terms (`` `body-parser` ``, `` `useState` ``)
or multi-line code samples with their own template literals (`` `Hello ${name}` `` inside example
code). Every field's delimiter type must never appear unescaped inside that same field's own content:
- If the field is a template literal (`` `...` ``): every backtick character inside its text — including
  ones from a nested code sample's own template literal, or from writing a technical term in backtick
  code-formatting — must be escaped as `` \` ``, and every `${` that isn't a real, intended interpolation
  must be escaped as `\${`.
- If the field is double-quoted (`"..."`): every literal `"` character inside its text must be escaped
  as `\"`.
One unescaped delimiter character silently ends the string early and corrupts everything after it in
the file — this has been the single most common reason a generation gets rejected. Before outputting,
mentally re-scan every field for exactly this.
